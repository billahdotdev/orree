## ১. অর্ডার Google Sheet-এ সেভ করা

অর্ডার ফর্ম সাবমিট হলে **সাথে সাথেই** ডেটা শিটে চলে যায় — গ্রাহক পরে WhatsApp-এ
মেসেজ পাঠাক বা না পাঠাক, অর্ডারটি তোমার কাছে রেকর্ড হয়ে থাকবে।

1. একটা নতুন Google Sheet খোলো (নাম দাও, যেমন "Orree Orders")
2. **Extensions → Apps Script** — স্টার্টার কোড মুছে `google-apps-script/Code.gs`
   ফাইলের পুরো কনটেন্ট পেস্ট করো
3. **Deploy → New deployment →** গিয়ার আইকন **→ Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
4. **Deploy** চাপো, permission দাও, তারপর **Web App URL** কপি করো
5. GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `VITE_SHEETS_WEBHOOK_URL`
   - Value: কপি করা URL
6. আবার push দাও — GitHub Actions অটোমেটিক এই URL বিল্ডে বসিয়ে দেবে

> লোকাল টেস্টের জন্য: `.env.example` কপি করে `.env` বানাও, সেখানে URL বসাও।

## ২. Telegram-এ ইনস্ট্যান্ট নোটিফিকেশন

প্রতিটা অর্ডারে তোমার ফোনে সাথে সাথে পুশ নোটিফিকেশন আসবে, সাথে একটা বাটন —
যেটাতে চাপলে সরাসরি ওই কাস্টমারের WhatsApp চ্যাট খুলে যাবে।

1. Telegram-এ **@BotFather**-কে মেসেজ করো → `/newbot` → নাম দাও
   → সে তোমাকে একটা **BOT TOKEN** দেবে
2. তোমার নতুন বটকে একবার "hi" মেসেজ করো (নাহলে বট তোমাকে মেসেজ পাঠাতে পারবে না)
3. ব্রাউজারে খোলো (`<TOKEN>` জায়গায় তোমার টোকেন বসাও):
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
   → `"chat":{"id":123456789` — এই নম্বরটাই তোমার **CHAT ID**
4. Apps Script-এ `TELEGRAM_BOT_TOKEN` ও `TELEGRAM_CHAT_ID` বসাও
5. **Deploy → Manage deployments →** পেন্সিল আইকন **→ Version: New version → Deploy**

> টিমের সবাই নোটিফিকেশন পেতে চাইলে: একটা Telegram গ্রুপ বানাও, বটকে গ্রুপে
> অ্যাড করো, গ্রুপে একটা মেসেজ দাও, তারপর গ্রুপের (নেগেটিভ) id ব্যবহার করো।

## ৩. ট্র্যাকিং আইডি বসানো

ট্র্যাকিং আইডি আর কোডে হার্ডকোড করা নেই — **env ভেরিয়েবল** থেকে বিল্ড-টাইমে
বসে। Cloudflare Pages → **Settings → Environment variables**-এ যোগ করো:

| ভেরিয়েবল | কী দিয়ে |
|---|---|
| `VITE_GA4_ID` | তোমার GA4 Measurement ID (`G-XXXXXXXXXX`) |
| `VITE_META_PIXEL_ID` | তোমার Meta Pixel / Dataset ID |

খালি রাখলে সেই ট্র্যাকারটা একেবারেই লোড হয় না (কোনো এরর নেই, কোনো ডেটা
placeholder-এ যায় না)। `index.html`-এর স্ক্রিপ্ট নিজেই এটা যাচাই করে।

**CAPI (Conversions API) — সার্ভার-সাইড, ঐচ্ছিক কিন্তু রেডি:**
`functions/api/capi.js` একটা Cloudflare Pages Function — ব্রাউজারের ইভেন্ট
সার্ভার থেকে Meta-তে পাঠায় (Pixel + CAPI একই `event_id` শেয়ার করে, তাই Meta
ডুপ্লিকেট গোনে না)। চালু করতে Cloudflare-এ **Encrypted** env হিসেবে দাও:

| ভেরিয়েবল (VITE_ নয়!) | কী দিয়ে |
|---|---|
| `META_PIXEL_ID` | `VITE_META_PIXEL_ID`-এর মতোই একই আইডি |
| `META_CAPI_TOKEN` | Events Manager → Conversions API access token |

এই দুটো সেট না করা পর্যন্ত `/api/capi` নীরবে কিছু করে না — সাইট আগের মতোই চলে।
টোকেন কখনো ব্রাউজারে যায় না।

## ৫. ডিপ্লয় — GitHub (Private) → Cloudflare Pages

সাইটটা Cloudflare Pages-এর জন্য সম্পূর্ণ রেডি। একবার সেটআপ করলে, এরপর
`main`-এ push করলেই Cloudflare অটো বিল্ড ও ডিপ্লয় করবে।

**একবারের সেটআপ:**
1. কোডটা তোমার **GitHub private repo**-তে push করো (`git init … git push`)।
2. Cloudflare Dashboard → **Workers & Pages → Create → Pages → Connect to Git**
   → তোমার repo বেছে নাও।
3. Build সেটিংস:
   - **Framework preset:** Vite (বা None)
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
   - **Node version:** `.nvmrc` থেকে ২০ অটো ধরবে (নাহলে env-এ
     `NODE_VERSION=20` দাও)
4. **Environment variables** যোগ করো (সেকশন ৩ + নিচের তালিকা):
   - `VITE_SHEETS_WEBHOOK_URL` — Apps Script URL
   - `VITE_TURNSTILE_SITE_KEY` — Turnstile site key (ঐচ্ছিক)
   - `VITE_GA4_ID`, `VITE_META_PIXEL_ID` — ট্র্যাকিং (ঐচ্ছিক)
   - `META_PIXEL_ID`, `META_CAPI_TOKEN` — CAPI, **Encrypted** (ঐচ্ছিক)
   - `VITE_BASE_PATH` **সেট কোরো না** — সাইট রুটে (`/`) থাকবে।
5. **Save and Deploy**। প্রথম বিল্ডের পর একটা `*.pages.dev` URL পাবে।

**কাস্টম ডোমেইন (`orree.bd`):** Pages প্রজেক্ট → **Custom domains → Set up a
domain** → `orree.bd` → Cloudflare DNS-এ CNAME অটো যোগ হবে (ডোমেইনটা
Cloudflare-এ থাকলে)। SSL ফ্রি ও অটো।

**যে ফাইলগুলো Cloudflare-কে সাহায্য করে (রেডি করা আছে):**
- `public/_redirects` — SPA fallback (যেকোনো ডিপ লিংক, যেমন `/candy`,
  `/lp/eid-offer`, রিফ্রেশেও ঠিক রুট দেখায়)।
- `public/_headers` — সিকিউরিটি হেডার + ক্যাশিং (হ্যাশড অ্যাসেট immutable,
  `index.html` no-cache)।
- `functions/api/capi.js` — Meta CAPI relay (env দিলে চালু)।

### AI ও SEO ফাইল (public/-এ রেডি)

- `robots.txt` — সার্চ ইঞ্জিন + বড় AI ক্রলার (GPTBot, ClaudeBot,
  PerplexityBot, Google-Extended ইত্যাদি) স্বাগত; `/admin` ও `/lp/*` বন্ধ।
- `llms.txt` — AI অ্যাসিস্ট্যান্টদের জন্য ব্র্যান্ড/প্রোডাক্টের কাঠামোবদ্ধ সারসংক্ষেপ।
- `sitemap.xml` — মূল পেজগুলো।
- `og-image.jpg` (1200×630) — সোশ্যাল শেয়ার প্রিভিউ; index.html-এ OG/Twitter
  ট্যাগ, canonical, Organization structured data সব বসানো।

### Hardening (ঐচ্ছিক — Content-Security-Policy)

`public/_headers`-এ ইচ্ছাকৃতভাবে CSP রাখিনি, কারণ Google Fonts, GA, Meta
Pixel, Turnstile, Apps Script — সব allow-list করতে হয়। চালু করতে চাইলে
`_headers`-এ `/*` ব্লকে যোগ করতে পারো (আগে ভালো করে টেস্ট করে নিও):

```
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' https://www.googletagmanager.com https://connect.facebook.net https://challenges.cloudflare.com; connect-src 'self' https://www.google-analytics.com https://*.googleapis.com https://script.google.com https://script.googleusercontent.com; img-src 'self' data: https:; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; frame-src https://challenges.cloudflare.com;
```

## ৬. অ্যাডমিন প্যানেল ও নিরাপত্তা

`/admin` পেজে পাসওয়ার্ড দিয়ে ঢুকলে চারটা ট্যাব পাওয়া যায় — সবগুলো একসাথে
**সেভ করুন** চাপলে Google Sheet-এ চলে যায় ও সাইটে সাথে সাথে লাইভ হয়:

- **প্রোডাক্ট** — নতুন যোগ, মুছে ফেলা, উপরে-নিচে সাজানো, নাম/দাম/আগের দাম/
  ওজন/উপাদান/উপকারিতা/স্টক, আর **একাধিক ছবি** (গ্যালারি)।
- **ল্যান্ডিং পেজ** — মেটা এডের অফার-পেজ (নিচে সেকশন ৬ক দেখো)।
- **হিরো ও গল্প** — মূল সাইটের হেডলাইন, সাব-টেক্সট, বাটন, ব্র্যান্ড স্টোরি।
- **ডেলিভারি** — ডেলিভারি চার্জ ও ফ্রি-ডেলিভারি থ্রেশহোল্ড।

### পাসওয়ার্ড কীভাবে ম্যানেজ করবে

পাসওয়ার্ড আর কোডে হার্ডকোড করা নেই — Apps Script-এর **Script Properties**-এ
থাকে, তাই কোড শেয়ার/কমিট করলেও ফাঁস হয় না।

**সেট করতে বা বদলাতে (দুটোরই একই ধাপ):**
1. Apps Script এডিটর খোলো → উপরে ফাংশন-ড্রপডাউন থেকে **`setAdminPassword`** বেছে নাও।
2. `Code.gs`-এ `setAdminPassword` ফাংশনের ভেতরে `NEW_PASSWORD = "CHANGE_ME"` লাইনটা
   বদলে নিজের পাসওয়ার্ড লেখো (লম্বা প্যাসফ্রেজ ভালো, যেমন `amar-orree-2026-Khulna!`)।
3. একবার **Run** চাপো → পাসওয়ার্ড সেভ হয়ে যাবে। ব্যস — সাইটের কোড বা ডিপ্লয়মেন্টে
   কিচ্ছু বদলাতে হবে না, নতুন পাসওয়ার্ড সাথে সাথে কার্যকর।

> বিকল্প: এডিটরে ⚙️ **Project Settings → Script Properties → Add** →
> Property `ADMIN_PASSWORD`, Value = তোমার পাসওয়ার্ড।

সেট না করা পর্যন্ত `Code.gs`-এর `ADMIN_PASSWORD_FALLBACK` ব্যবহার হয় — তাই
**লাইভ যাওয়ার আগে অবশ্যই একবার `setAdminPassword` চালাবে।**

### নিরাপত্তা কীভাবে কাজ করে (এবং কী করে না)

সাইটটি স্ট্যাটিক — ব্রাউজারে পাঠানো যেকোনো কোড যে কেউ পড়তে পারে। তাই:

- ✅ **পাসওয়ার্ড ওয়েবসাইটের কোডে নেই** — অ্যাডমিন টাইপ করেন, Apps Script
  সার্ভারে যাচাই করে। কেউ কোড পড়ে পাসওয়ার্ড বের করতে পারবে না।
- ✅ **প্রতিটা সেভে সার্ভার আবার পাসওয়ার্ড যাচাই করে** — কেউ ব্রাউজারে
  লগইন স্ক্রিন বাইপাস করলেও, সঠিক পাসওয়ার্ড ছাড়া কিছু বদলাতে পারবে না।
- ⚠️ **লগইন স্ক্রিনটা নিজে কোনো দেয়াল নয়** — আসল দেয়ালটা সার্ভারে।
  এটাই স্ট্যাটিক সাইটে সম্ভব সবচেয়ে শক্ত ব্যবস্থা।

আরও শক্ত নিরাপত্তা দরকার হলে (একাধিক ইউজার, অ্যাক্সেস লগ, সেশন মেয়াদ)
তখন Supabase বা Firebase Auth-এ যাওয়াই সঠিক পদক্ষেপ।

## ৬ক. মেটা এডের জন্য নতুন অফার ল্যান্ডিং পেজ লঞ্চ করা

প্রতিটি অফার একটা আলাদা পেজ — ঠিকানা `/lp/<তোমার-slug>` (যেমন
`orree.bd/lp/eid-offer`)। **কোড ছোঁয়া বা রিডিপ্লয় ছাড়াই** এগুলো বানানো,
বদলানো ও বন্ধ করা যায়।

**নতুন অফার লঞ্চের ৩ ধাপ:**
1. `/admin` → **ল্যান্ডিং পেজ** ট্যাব → **নতুন ল্যান্ডিং পেজ যোগ করুন**।
2. পূরণ করো: একটা **slug** (লিংক-নাম), কোন প্রোডাক্ট, আর যা যা অফারে বদলাতে
   চাও — হেডলাইন, ছবি, **অফার মূল্য + আগের দাম**, ব্যাজ, বাটনের লেখা।
   *(যে ঘর খালি রাখবে, সেটা প্রোডাক্টের নিজের তথ্য থেকে পূরণ হবে।)*
   চাইলে একটা **সৎ অফার-ডেডলাইন** দাও — সময় পেরোলে কাউন্টডাউন নিজেই মিলিয়ে যাবে।
3. **সেভ করুন** → কার্ডের **কপি** বাটনে চাপো → লিংকটা মেটা Ads Manager-এ
   বসাও। ব্যস, অফার লাইভ।

**অফার শেষ হলে:** সেই কার্ডের **দৃশ্যমানতা টগল** বন্ধ করে সেভ করো — লিংকটা
তখন নিষ্ক্রিয় হয়ে যাবে (৪০৪ দেখাবে), কিন্তু চাইলে পরে আবার চালু করা যাবে।

**ট্র্যাকিং:** প্রতিটি ল্যান্ডিং পেজে একটা **সোর্স লেবেল** দেওয়া যায় (যেমন
`eid-meta`) — অর্ডারের সাথে সেটা Google Sheet-এর "Source" কলামে চলে যায়,
তাই কোন এড থেকে কত অর্ডার এলো সহজে দেখা যায়।

> ⚠️ **সোশ্যাল-শেয়ার প্রিভিউ নোট:** স্ট্যাটিক হোস্টিংয়ে প্রতি পেজের আলাদা
> লিংক-প্রিভিউ (OG ইমেজ/টাইটেল) সম্ভব নয় — সব `/lp/...` পেজে সাইটের একই
> প্রিভিউ দেখাবে। তবে **মেটা এডের ছবি ও লেখা তুমি Ads Manager-এই সেট করো**,
> পেজের OG থেকে নয় — তাই এড চালাতে এটা কোনো সমস্যা নয়। শুধু লিংকটা
> organically শেয়ার করলে প্রিভিউ একই আসবে। আসল per-page প্রিভিউ লাগলে
> Cloudflare Pages + prerendering-এ যেতে হবে (সেকশন ৮ দেখো)।

## ৭. ফেক অর্ডার / স্প্যাম প্রতিরোধ

সুরক্ষার আসল স্তরটা Apps Script-এ (সার্ভারে) — যেটা কেউ ব্রাউজার থেকে বদলাতে পারে না:

| ব্যবস্থা | কোথায় | আসল কাস্টমার টের পায়? |
|---|---|---|
| **Cloudflare Turnstile** (বট চ্যালেঞ্জ) | ক্লায়েন্ট + সার্ভার | না (অদৃশ্য) |
| হানিপট ফিল্ড (বটরা পূরণ করে, মানুষ দেখেই না) | ক্লায়েন্ট + সার্ভার | না |
| ৩ সেকেন্ডের কমে সাবমিট = বট | সার্ভার | না |
| একই ফোন + একই টাকা, ১০ মিনিটে পুনরায় = ডুপ্লিকেট | সার্ভার | না |
| এক ফোন থেকে ঘণ্টায় সর্বোচ্চ ৩ অর্ডার | সার্ভার | না |
| ফোন নম্বরের ফরম্যাট যাচাই | সার্ভার | না |
| ৯০ সেকেন্ড কুলডাউন | ক্লায়েন্ট | শুধু দ্রুত পুনরায় অর্ডার করলে |

### Cloudflare Turnstile সেটআপ

Turnstile সাধারণ ক্যাপচার মতো ছবি বাছাই করায় না — আসল মানুষের জন্য প্রায়
সবসময়ই অদৃশ্য থাকে। শুধু সন্দেহজনক ট্রাফিক চ্যালেঞ্জ দেখে।

1. https://dash.cloudflare.com → **Turnstile → Add site** (ফ্রি)
2. Widget mode: **Managed**
3. Hostnames-এ যোগ করো:
   - `yourusername.github.io` (এখনকার টেস্টিং)
   - `orree.bd` (পরে, কাস্টম ডোমেইনে গেলে)
   - `localhost` (লোকাল ডেভেলপমেন্টে)
4. দুটো কী পাবে:
   - **Site key** → GitHub secret `VITE_TURNSTILE_SITE_KEY` (পাবলিক, সমস্যা নেই)
   - **Secret key** → Apps Script-এর `TURNSTILE_SECRET_KEY` (ব্রাউজারে কখনো যাবে না)
5. Apps Script আবার deploy করো (নতুন version)

⚠️ **দুটো কী-ই বসাতে হবে।** শুধু Site key বসালে উইজেট দেখাবে কিন্তু কোনো
সুরক্ষা দেবে না — কারণ যাচাইটাই হবে না। Secret key ছাড়া Turnstile নিষ্ক্রিয়।

**ইচ্ছাকৃত ডিজাইন — সমস্যা হলে অর্ডার আটকাবে না:** Turnstile স্ক্রিপ্ট লোড না
হলে (অ্যাড ব্লকার, দুর্বল নেট) বা Cloudflare ডাউন থাকলে অর্ডার তবুও যাবে,
বাকি স্প্যাম নিয়মগুলো কাজ করতে থাকবে। ছোট COD ব্যবসায় একজন আসল ক্রেতা
হারানো একটা বট ঢোকার চেয়ে অনেক বেশি ক্ষতিকর।

ব্লক হওয়া সাবমিশনগুলো **"Rejected"** শিটে জমা হয় — মাঝে মাঝে দেখে নিও, যদি
কোনো আসল কাস্টমার ভুলে আটকে যান।

**সীমাবদ্ধতা যা জানা দরকার:** IP-ভিত্তিক ব্লকিং Apps Script দিয়ে নির্ভরযোগ্যভাবে
করা যায় না। Turnstile বেশিরভাগ স্বয়ংক্রিয় স্প্যাম আটকাবে, কিন্তু কেউ যদি হাতে
নিজে ভিন্ন ভিন্ন ফোন নম্বর দিয়ে অর্ডার করতে থাকে, সেটা কোনো কারিগরি ব্যবস্থাই
পুরোপুরি থামাতে পারবে না। Cloudflare Pages-এ সরানোর পর **Cloudflare Functions**
দিয়ে আসল IP rate limiting যোগ করা যাবে।

⚠️ **যেহেতু COD**: সবচেয়ে বড় সুরক্ষা কারিগরি নয় — অর্ডার ডেলিভারিতে পাঠানোর
আগে অচেনা/সন্দেহজনক অর্ডারে একবার ফোন করে কনফার্ম করে নেওয়া।

## ৮. Cloudflare Functions (IP rate limiting, ভবিষ্যতে)

সাইট এখন Cloudflare Pages-এ চলে (সেকশন ৫), তাই `functions/` ফোল্ডারে
সার্ভার-সাইড কোড যোগ করা যায়। CAPI relay (`functions/api/capi.js`) এভাবেই
বসানো। একইভাবে ভবিষ্যতে **আসল IP-ভিত্তিক rate limiting** বা Turnstile
সার্ভার-যাচাই যোগ করা যাবে — যেটা Apps Script দিয়ে নির্ভরযোগ্যভাবে করা যায় না।

## ৯. ভবিষ্যতে আসল ব্যাকএন্ড/ডাটাবেজ যোগ করা

কোডটা এমনভাবে সাজানো যে ব্যাকএন্ড বদলাতে **UI-র একটাও ফাইল ছুঁতে হবে না**।
সব বাইরের যোগাযোগ মাত্র দুটো ফাইলের ভেতরে আটকানো:

```
src/services/orderService.js    ← অর্ডার কোথায় যাবে
src/services/contentService.js  ← প্রোডাক্ট ডেটা কোথা থেকে আসবে
```

**Supabase-এ সরাতে চাইলে** (ফ্রি Postgres + অটো API + Auth):

1. `orderService.js`-এ `logToSheet()` ফাংশনের ভেতরের `fetch` URL বদলে
   Supabase-এর REST endpoint দাও — বাকি কোড অপরিবর্তিত
2. `contentService.js`-এ `fetchProducts()` / `saveProducts()` একইভাবে বদলাও
3. অর্ডারের `order` অবজেক্টের গঠন (id, customer, items, subtotal,
   deliveryFee, total, channel, source) ইচ্ছে করেই ডাটাবেজ-বান্ধব রাখা
   হয়েছে — সরাসরি একটা টেবিলে ম্যাপ করা যাবে

`OrderForm.jsx`, `AdminPanel.jsx`, ল্যান্ডিং পেজ — কোনোটাই জানে না ডেটা কোথায়
যাচ্ছে, তাই কোনোটাই বদলাতে হবে না।

## ১১. প্রোডাক্টের ছবি (সবচেয়ে জরুরি বাকি কাজ)

ছবি যোগ করা সহজ: ছবিগুলো `public/products/` ফোল্ডারে রাখো, তারপর `/admin`
পেজে প্রতিটা প্রোডাক্টের "ছবির লিংক" ঘরে লেখো `/products/candy.jpg` —
সেভ করলেই SPA ও ল্যান্ডিং পেজ দুই জায়গাতেই চলে আসবে।

**ফোনেই ভালো ছবি তোলার কয়েকটা নিয়ম:**

- **জানালার পাশে দিনের আলোয় তোলো** — ফ্ল্যাশ কখনো নয়। ফ্ল্যাশ খাবারকে
  চ্যাপ্টা ও কৃত্রিম দেখায়।
- **ব্যাকগ্রাউন্ড সাদামাটা রাখো** — সাদা কাগজ, কাঠের টেবিল, বা পাটের চট।
  Orree-র ব্র্যান্ডের সাথে গাঢ় সবুজ বা ক্রিম রঙের কাপড়ও দারুণ মানাবে।
- **প্রতি প্রোডাক্টে অন্তত ৩টা ছবি**: (১) প্যাকেটসহ পুরো প্রোডাক্ট,
  (২) খুলে ভেতরের জিনিস কাছ থেকে, (৩) কেউ হাতে ধরে আছে — তৃতীয়টা সবচেয়ে
  বেশি বিশ্বাস তৈরি করে।
- **ছবি স্কয়ার (1:1) করে কেটে নাও**, আর আপলোডের আগে সাইজ কমাও
  (squoosh.app — ফ্রি)। ১০০-২০০ KB-র মধ্যে রাখলে মোবাইলে দ্রুত লোড হবে।

**একাধিক ছবি দিলে** প্রোডাক্ট কার্ড ও ল্যান্ডিং পেজে **সোয়াইপ গ্যালারি** হয়ে
যাবে, আর ট্যাপ করলে **ফুলস্ক্রিন জুম** — এই ফিচার তৈরি আছে, শুধু ছবি বসানোই বাকি।
